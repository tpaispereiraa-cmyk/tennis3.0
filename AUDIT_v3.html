Confirmações do Patch v1.2

Todos os 8 itens do Patch v1.1 e os 5 itens do Patch v1.2 estão ativos e verificados. Esta seção confirma o estado atual antes de listar os novos achados desta rodada.
CONFIRMADO v1.1
target.y dinâmico + predY adaptativo — jogadores se movem em Y
ai.js → updatePlayer()

Clamp corrigido (v1.2): side > 0 usa [basePos.y − maxForward, basePos.y + maxBack]. Verificado via simulação: drop shot em y=2, jogador avança para y=8.985 (2.5m da baseline). Correto.

yFrac fallback também corrigido com yMin/yMax por side. CTR_PUNCHER/RETRIEVER override igualmente corrigido.

CONFIRMADO v1.2
3 atributos mortos ligados: srv1Prec, varSaque, coberturaLob
players.js → computePlayerMods() · game.js → tickServing() · ai.js → updatePlayer()

srv1Prec: serveScatter agora aplicado em tickServing(): tX += (Math.random() − 0.5) * sScatter * 0.8. SERVOLEY (prec=86): ±0.216m de desvio. RAIVOSINHO (prec=66): ±0.264m.

varSaque: serveVarMult ajusta thresholds T/Wide/Body. SERVOLEY (var=90): ~33%T/32%Wide/35%Body. Jogadores de baixa variação ficam T-heavy.

coberturaLob: lobCovMult define lobZ threshold de recuo de rede. COUTERZITUS (cob=88): reage a z=1.32m. PANCADÃO (cob=54): z=1.46m. Diferença perceptível em jogo rápido.

Novos Achados — Auditoria v3

CORRIGIDO AGORA
THRESHOLDS.errorRallyMin = 1 — fix de patience só valia para jogadores nomeados
src/constants.js linha 23 · src/game.js tryHit()

O fix #6 do patch v1.1 atualizou computePlayerMods() para retornar patienceRallyMin = Math.round(2 + ...). Mas em tryHit(), o fallback para jogadores genéricos (sem atributos nomeados) ainda lia THRESHOLDS.errorRallyMin, que permanecia em 1. Resultado: qualquer partida sem jogadores nomeados continuava errando no rally 2.

Antes — constants.js
reachStretch: 0.75, errorRallyMin: 1, netZone: 1.8,
Depois — constants.js
reachStretch: 0.75, errorRallyMin: 2, netZone: 1.8,
CORRIGIDO AGORA
underPressure sticky — ficava true o rally inteiro após um único momento de pressão
src/game.js → tryHit() · comportamento CTR_PUNCHER e RETRIEVER

underPressure era setado true quando ball.pos.z < 0.45 (bola baixa) ou diff > 0.65 (esticado para pegar). Só resetava em resetCtx() — entre pontos. Numa troca de 10 bolas, um único momento defensivo no rally 3 mantinha o jogador em modo defensivo até o ponto acabar.

Impacto real: CTR_PUNCHER com underPressure=true dispara SLICE 40% das vezes ao invés de TOPSPIN 55%. Se o CTR_PUNCHER se recupera e está em posição ideal, ainda joga como se estivesse defendendo. Idêntico para RETRIEVER (SLICE 50% quando em pressão).

Antes — game.js tryHit()
  const diff = Math.min(1, d / effectiveReach);
  if (ball.pos.z < THRESHOLDS.pressureBallZ || diff > THRESHOLDS.pressureReach)
    player.ctx.underPressure = true;
  // Nunca volta para false no meio do rally
Depois — game.js tryHit()
  const diff = Math.min(1, d / effectiveReach);
  if (ball.pos.z < THRESHOLDS.pressureBallZ || diff > THRESHOLDS.pressureReach)
    player.ctx.underPressure = true;
  // Recupera: se a bola está alta e o jogador não está esticado, sai do modo defensivo
  else if (diff < 0.45 && ball.pos.z >= 0.55)
    player.ctx.underPressure = false;
Resultado: CTR_PUNCHER e RETRIEVER agora respondem taticamente ao momento atual do rally, não ao pior momento já vivido. Uma defesa difícil no rally 3 não mais contamina todos os shots do rally 5 ao 12.
CORRIGIDO AGORA
SRV_VOL rushNetAfterServe — guarda lobsReceived < 2 era dead code
src/game.js → tickServing() linha final

lobsReceived é resetado para 0 em resetCtx() entre pontos. No momento do saque, lobsReceived é sempre 0. A condição sv.ctx.lobsReceived < 2 era sempre true, tornando a guarda completamente inerte. SRV_VOL subia à rede em todo saque incondicionalmente, mesmo que o design pretendesse suprimir isso após receber muitos lobs no ponto anterior.

A intenção correta da supressão de rede está implementada no netSuppressed dentro do rally (após receber 2 lobs no ponto em andamento). A linha no serve era redundante e confusa.

Antes
if (sStyle.rushNetAfterServe && sv.ctx.lobsReceived < 2) sv.atNet = true;
// lobsReceived = 0 sempre aqui → condição always true → dead code
Depois
if (sStyle.rushNetAfterServe) sv.atNet = true;
// Supressão de rede acontece corretamente durante o rally via netSuppressed
CORRIGIDO AGORA
tickPreServe — receiver retornava a y fixo, ignorando baselineOffset do estilo
src/game.js → tickPreServe()

O receiver interpolava sua posição pré-saque para side * (COURT.halfL − 0.5) = fixo para todos os estilos. RETRIEVER (offset=0.2m) deveria começar em y=11.685m; CTR_PUNCHER (offset=0.3m) em y=11.585m. Ambos ficavam em 11.385m — ligeiramente adiantados da posição de retorno correta.

Antes
rv.pos.y += (rv.side * (COURT.halfL - 0.5) - rv.pos.y) * 0.08;
Depois
const rvBaseY = rv.side * (COURT.halfL - rv.styleData.baselineOffset);
rv.pos.y += (rvBaseY - rv.pos.y) * 0.08;

Física — A−

Status: Sem alterações desde v1. Motor sólido. A única razão para não ser A é que o impacto da stamina no jogo, embora funcional, é linear — não há diferença qualitativa entre 30% de stamina e 10% de stamina além de escala contínua de velocidade/erro.
✓ FÍSICA Magnus effect, drag aerodinâmico, bounce com topspin/backspin separados, sidespin lateral — todos corretos e interativos.
✓ PREDIÇÃO predictTrajectory() usa os mesmos coeficientes que o motor real. Predições de trajetória são matematicamente fiéis ao comportamento real da bola.
✓ STAMINA decay=0.032 + recovery=0.18 funcional. Jogador a 0 stamina: velocidade 78%, reach 83%, +2.2% taxa de erro. Recuperação total em ~6 pontos.
✓ QUALIDADE Posicionamento: distQuality×0.30 + timingQuality×0.45 + moveQuality×0.25. Ponderação bem calibrada. Timing domina, como deveria.

Movimento — A−

Meta atingida. Jogadores agora se movem corretamente em X e Y, avançam para bolas curtas, recuam para bolas profundas, retornam à base após bater. predY adaptativo funciona para drop shots. O clamp foi corrigido para os dois players (side ±1).
✓ INTERCEPTAÇÃO Y maxForward=2.5m em direção à rede. Drop shot a 2m da rede: player avança até 8.99m (2.5m da baseline de 11.49m). Verificado numericamente.
✓ DROP SHOT predY adaptativo: bola curta (<4.5m da rede) usa 0.25×halfL ao invés de 0.55×halfL. crossPoint agora detectado corretamente para bolas curtas.
✓ OFFSET DINÂMICO dynamicOffset por momentum: pressão → recua 0.6m; confiança → avança 0.3m. Fórmula: baselineOffset + clamp((0.5−mom)×1.2, −0.3, 0.6).
↑ BASELINE AGG_BASELINER 1.5m→0.4m · ALL_COURT 1.2m→0.5m · BIG_SERVER 1.0m→0.3m. Jogadores jogam da linha de base, não do meio da quadra.
Nota: Observação ainda válida do v2 — após rebater a bola, o jogador retorna a basePos.y imediatamente. Não há recuperação de posição lateral (centralizar em X após atingir bola lateral). O playerBasePos.x é fixado em 0 (centro da quadra) que é correto, mas a transição poderia ter um leve delay proporcional à qualidade do shot para parecer mais natural. Classificado como refinamento futuro, não bug.

Comportamento — B+

underPressure corrigido nesta rodada. CTR_PUNCHER e RETRIEVER agora respondem ao momento atual do rally. Os demais sistemas de comportamento permanecem funcionais.
✓ MOMENTUM Sistema de momentum com memória tática. Pesos de shot, agressividade e agresDecFactor todos modulados por momentum. Implementação sólida.
✓ PACIÊNCIA patienceRallyMin range 2–7. RAIVOSINHO (paciência=40): min 4 balls antes de errar. COUTERZITUS (paciência=82): min 6. Agora válido também para genéricos (errorRallyMin=2).
✓ UNDERPRESS underPressure agora reseta quando diff < 0.45 e ball.z ≥ 0.55. Pressão é situacional, não permanente.
✓ NET CAP Caps por estilo: RETRIEVER max 6%, CTR_PUNCHER max 14%. Baselines não viram serve-volleyers com instintoRede alto.
✓ SCATTER Scatter em X e Y sob pressão. quality=0 → ±2.2m horizontal + ±18% de profundidade. Erros defensivos soam realistas.
